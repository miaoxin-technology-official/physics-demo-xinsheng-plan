# 开源、许可证与法律效力——写给物理老师看的说明

> 您做了一个物理动画，希望放到这个仓库里供同行使用。别人自然会问：能不能用于课堂？能不能修改？是否需要付费？是否需要署名？
>
> 这些问题，靠「许可证」一次性回答清楚。本文讲明白四件事：**版权、开源、许可证类型、法律效力**。

---

## 一、版权：一切的前提

### 1. 作品完成，版权自动产生

在中国以及绝大多数国家，**作品一经完成，著作权自动产生**，不需要登记，也不需要发表或盖章。

您编写的 HTML、绘制的图、录制的音频，从保存那一刻起，版权即归您所有。

### 2. 默认状态是「保留所有权利」

如果没有任何声明，法律默认：**他人不得复制、修改、再发布。**

这并非作者苛刻，而是法律的默认设置。问题在于：使用者不知道您是否允许，往往就不敢使用。

### 3. 版权包含哪些权利

- **署名权**：标明作者身份；
- **复制权**：复制作品；
- **发行权**：向他人提供原件或复制件；
- **修改权 / 改编权**：修改作品或创作衍生作品；
- **信息网络传播权**：通过网络提供作品，供他人浏览、下载。

许可证的作用，就是您把其中一部分权利**有条件地**授予他人。

---

## 二、什么是许可证

### 1. 定义

**许可证（License）是版权人向公众作出的授权声明：在满足特定条件的前提下，允许使用其作品。**

它不是转让版权，也不是放弃版权，而是**授权**。

### 2. 一个类比

您把自制的教具借给同事，口头说「可以用，但请注明是我做的」——这是口头许可。

如果您把教具放在器材室，贴一张说明：「欢迎使用，可自行改装，请注明制作者」——这张说明就相当于许可证。

LICENSE 文件，就是放在课件旁边的那张说明。

### 3. 许可证附带条件

常见条件包括：

- **署名（BY）**：使用时注明原作者；
- **相同方式共享（SA）**：修改后发布，须采用同样的许可证；
- **非商业（NC）**：不得用于商业目的；
- **禁止演绎（ND）**：不得修改。

**条件不是建议，而是授权的前提。** 违反条件，授权即失效——这一点在第五节详细说明。

### 4. 许可证不改变版权归属

作者仍然是著作权人。许可证只是承诺：符合条件的使用者，无需再单独取得授权。

## 三、什么是「开源」

### 1. 起源与含义

「开源」（Open Source）最初用于软件，指**源代码公开，并允许任何人使用、研究、修改和再分发**。

自由软件基金会将其概括为四项自由：

1. 为任何目的运行程序；
2. 研究程序的工作方式，并按需修改；
3. 再分发副本；
4. 改进程序，并向公众发布改进版本。

### 2. 开源不等于免费

这是最常见的误解。

> Free as in freedom, not free as in beer.
> （自由，而非免费。）

开源强调的是**使用与修改的自由**，与是否收费无关。开源软件完全可以收费，也可以用于商业项目。

### 3. 开源不限于软件

课件属于内容作品（文字、图片、动画、音视频），对应的开放许可主要是 **Creative Commons（CC）** 系列。

因此本仓库同时涉及两类许可：

- **代码部分**（HTML / JavaScript）→ 常用 MIT 等软件许可证；
- **内容部分**（图片、音频、动画素材）→ 常用 CC BY-SA 4.0 等内容许可证。

### 4. 开源的判定标准

一个作品要被称为「开源」，至少应满足：

- 允许免费再分发；
- 允许修改；
- 不歧视使用领域（包括商业使用）；
- 公开许可证文本。

仅公开源代码、但不允许修改或不允许商用的，属于「源码可见」，不属于开源。

## 四、许可证的类型

### 1. 宽松型（Permissive）

代表：**MIT、BSD、Apache-2.0**

特点：允许使用、修改、再发布，允许闭源，**但必须保留版权声明与许可证文本**。

| 许可证 | 说明 |
| --- | --- |
| **MIT** | 条款最短、最宽松，使用最广，适合大多数课件代码 |
| **BSD-2-Clause / BSD-3-Clause** | 与 MIT 接近；3-Clause 额外禁止用作者名义背书 |
| **Apache-2.0** | 含明确的**专利授权**条款，适合涉及专利风险的项目；与 GPL-3.0 兼容，与 GPL-2.0 不兼容 |

### 2. 传染型 / 著佐权（Copyleft）

代表：**GPL 系列、MPL-2.0、CC BY-SA 4.0**

特点：允许使用、修改、商用，但**衍生作品须采用相同许可证**，部分许可证还要求提供源代码。

| 许可证 | 特点 |
| --- | --- |
| **GPL-2.0** | 分发时须提供源代码；衍生作品须为 GPL-2.0；与 Apache-2.0 不兼容 |
| **GPL-3.0** | 在 GPL-2.0 基础上增加专利授权、反规避条款；与 Apache-2.0 兼容 |
| **LGPL-2.1 / 3.0** | 弱传染：以动态链接方式使用库时，主程序可以不 adopt 同许可证；适合基础库 |
| **AGPL-3.0** | 强传染：通过网络提供服务也视为分发，须提供源代码；适合 Web 服务类项目 |
| **MPL-2.0** | 文件级传染：修改过的文件须保持 MPL，其他文件可以闭源 |
| **CC BY-SA 4.0** | 内容领域的「相同方式共享」，衍生作品须采用同一许可 |

> **GPL 的适用场景**：如果您希望「谁改了我的课件，谁就必须同样开源」，可以选 GPL。但要注意：学校把课件放到校内平台供学生使用，是否属于「分发」，需要结合具体情形判断，稳妥做法是随课件附上源代码和许可证。

### 3. 内容许可：Creative Commons 家族

CC 许可证由四个要素组合而成：

- **BY（署名）**：必须注明作者；
- **SA（相同方式共享）**：衍生作品须采用相同许可；
- **NC（非商业）**：不得用于商业目的；
- **ND（禁止演绎）**：不得修改。

常见组合：

| 许可证 | 可商用 | 可修改 | 衍生作品许可 | 备注 |
| --- | --- | --- | --- | --- |
| **CC BY 4.0** | ✅ | ✅ | 不限 | 最宽松的 CC 许可 |
| **CC BY-SA 4.0** | ✅ | ✅ | 必须同一许可 | 内容领域的「开源」 |
| **CC BY-NC 4.0** | ❌ | ✅ | 不限 | 不属于开源许可 |
| **CC BY-ND 4.0** | ✅ | ❌ | 不允许演绎 | 不属于开源许可 |
| **CC BY-NC-SA 4.0** | ❌ | ✅ | 必须同一许可 | 限制较多 |
| **CC BY-NC-ND 4.0** | ❌ | ❌ | 不允许演绎 | 限制最多 |

### 4. 公共领域 / 放弃权利型

| 许可证 | 说明 |
| --- | --- |
| **CC0 1.0** | 放弃大部分权利，不要求署名，可自由使用 |
| **Unlicense** | 类似公共领域，常用于小型代码 |

### 5. 专有许可 / 商业许可

「保留所有权利」，或通过单独合同授权。学校采购的正版课件多属此类。

### 6. 许可证兼容性（重要）

不同许可证之间并非都能混用：

- **MIT / BSD / Apache-2.0 的代码可以并入 GPL 项目**（宽松 → 传染，方向可行）；
- **GPL 代码不能直接改成 MIT 发布**（传染 → 宽松，方向不可行）；
- **Apache-2.0 与 GPL-2.0 不兼容**，与 GPL-3.0 兼容；
- **CC BY-SA 4.0 与 GPL 系列官方不兼容**，混用需谨慎；
- **CC BY-NC / ND 不属于开源许可**，不宜与开源代码混在一个项目中。

如果课件同时包含代码和素材，建议分别标注：

```text
- 代码：MIT
- 素材（图片、音频）：CC BY-SA 4.0
```

## 五、法律效力

### 1. 在中国法下的性质

许可证通常被认定为**著作权许可使用合同**，或版权人作出的单方授权声明。

- 不要求纸质签字，**电子形式、网页展示、仓库中的 LICENSE 文件均有效**；
- 使用者使用作品，即视为接受许可证条件；
- 受《著作权法》《民法典》合同编保护。

### 2. 违反许可证的后果

许可证的条件是授权的前提。违反条件，授权失效，使用行为即构成**未经许可的使用**。

例如：

- 使用 MIT 作品但删除作者署名；
- 将 GPL 代码修改后闭源发布；
- 将 CC BY-SA 作品修改后改用 MIT 发布。

可能的后果：

- 停止使用、下架、删除；
- 赔偿损失（按实际损失、侵权获利或法定赔偿计算）；
- 赔礼道歉、消除影响；
- 平台投诉，导致仓库或网站被封禁。

### 3. 司法实践

国内外已有多起法院认可开源许可证效力的案件：**违反许可证条件的使用，被认定为著作权侵权。**

中国法院在若干案件中确认了 GPL 等开源许可的合同约束力，并支持了权利人要求停止侵权、赔偿损失的请求。

> 具体裁判结果因案件事实而异，此处仅说明「许可证具有法律约束力」这一结论。

### 4. 免责条款的效力

开源许可证普遍包含 **AS IS**（按现状提供、不提供担保）条款：

- 作者不保证作品无错误，不承担使用后果；
- 此类条款通常有效，可降低作者风险；
- 但不能免除故意或重大过失责任，也不能违反法律强制性规定。

对使用者而言：使用他人课件开展教学，教学责任由使用者承担，原作者一般不承担（除非存在故意或重大过失）。

### 5. 授权能否撤回

- **已经按某一许可证发布的版本，授权不可撤销**：已获得授权的人可以继续按原条件使用；
- 作者可以停止发布新版本，或对新版本改用其他许可证；
- 但不能要求已获授权的人交回权利。

因此，**发布前应确定许可证，发布后不宜反复变更**。

### 6. 许可证不覆盖的内容

许可证只涉及**著作权**，以下内容不在其范围内：

- **商标**：不得因开源而使用作者的项目名、标识；
- **专利**：MIT 不含专利授权，Apache-2.0 含专利授权；
- **肖像权、隐私权**：课件中出现真人照片、学生画面，需本人同意；
- **第三方素材**：教材插图、商业图片、字体的版权不在作者手中，作者无权授权；
- **数据库权利、商业秘密**等其他权利。

这也是本仓库不接受教材插图和来源不明素材的原因——作者本人也没有权利授权这些内容。

### 7. 如何证明作品归属

- 保留原始文件、设计稿与提交记录（Git 历史自带时间戳）；
- 重要作品可进行著作权登记（非必需，但诉讼时是有力证据）；
- 公开发布记录、Issue / PR 讨论也可作为佐证。

## 六、如何选择

1. **主要提供代码还是素材？**
   - 代码为主 → **MIT**
   - 图片、音频、动画素材为主 → **CC BY-SA 4.0**

2. **是否希望衍生作品同样开放？**
   - 希望 → **CC BY-SA 4.0** 或 **GPL**
   - 无所谓 → **MIT**

3. **是否介意商业使用？**
   - 介意 → 标准开源许可均不禁止商业使用；带 NC 的许可会阻碍学校采购，**不建议**。
   - 不介意 → MIT、CC BY-SA 4.0 均可。

如无特殊要求，选择 **MIT** 最为稳妥：条款简单、学校接受度高、法律风险低。

## 八、常见误解

### 1. 放了许可证，版权就转移了？

不是。版权始终归作者所有，许可证只是有条件授权。

### 2. 开源等于免费？

不是。开源强调的是使用与修改的自由，不代表不能收费。

### 3. 他人能否拿我的课件营利？

MIT 与 CC BY-SA 4.0 均允许商业使用。这看似不利，但正是学校愿意采用的原因——采购流程不会因「禁止商用」而受阻。

### 4. 课堂使用需要许可证吗？

需要。课堂放映属于使用作品；学校将资源放到校内平台或统一采购时，会核查许可证。有 LICENSE 文件，流程才顺畅。

### 5. 能否使用教材插图？

不能。教材插图版权属于出版社，作者无权授权。请改用自绘图、明确可用的免费素材，或不用图。

### 6. AI 生成内容的版权归谁？

各国规定不一致。稳妥做法：

- README 注明哪些部分使用了 AI 辅助；
- 公式、方向、单位、文案由作者逐项核对；
- 不将 AI 生成的、来源可疑的内容视为原创素材。

### 7. 没有 LICENSE 会怎样？

默认「保留所有权利」，他人不敢使用，学校也难以收录。

### 8. 以后能否更改许可证？

可以，但仅对新版本有效；已按旧许可证获得的授权不能撤回。

### 9. 学生作品能否收录？

可以，但需学生本人（未成年人需监护人）同意，并署名。

### 10. 许可证文本能否自行改写？

不能。许可证是具有法律效力的标准文本，**请勿改写条款**，只修改年份和作者名。

### 11. GPL 课件能否放进这个仓库？

可以，只要符合 GPL 的要求（随附许可证、提供源代码、衍生作品保持 GPL）。但本仓库更推荐 MIT 或 CC BY-SA 4.0，因为条款更简单，学校使用门槛更低。

## 九、本仓库的要求

- 每个课件目录必须有 `LICENSE`；
- 推荐 **MIT** 或 **CC BY-SA 4.0**；
- README 与 LICENSE 的许可声明必须一致；
- 不接受：来源不明素材、教材插图、商业课件、反编译自 Flash 的内容；
- 仓库自身的索引、脚本、文档使用 MIT，见根目录 [LICENSE](../LICENSE)。
